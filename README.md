# Нормы — MVP по официальным документам

Однопроцессное Python-приложение со статическим HTML-интерфейсом. Оно отвечает на ситуационные вопросы по действующим версиям нормативных документов и делает структурированное резюме загруженного или выбранного документа.

В репозитории только **синтетический** демонстрационный корпус (`demo/normative_corpus.json`), а не официальные документы. Для реального контура задайте путь к утверждённому JSON-корпусу через `NORMATIVE_CORPUS_PATH`. Формат — JSON-массив с `document_id`, `title`, `version`, `effective_date`, `status`, `text` (и, при наличии, `clauses`). Для выбора победителя конфликта обязательны явные числовые `priority_rank`: меньшее число означает более высокий приоритет. Без этих метаданных приложение показывает конфликт, но не предполагает победителя.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

Откройте `http://127.0.0.1:8000`. Порт можно изменить: `APP_PORT=18000 .venv/bin/python app.py`. Официальный корпус подключается без изменения кода: `NORMATIVE_CORPUS_PATH=/absolute/path/official_corpus.json .venv/bin/python app.py`.

Docker-вариант:

```bash
docker build -t cps-hackathon-summary .
docker run --rm -p 8000:8000 cps-hackathon-summary
```

Файлы TXT, MD, CSV, JSON, DOCX и PDF извлекаются локально в памяти. PDF требует `pypdf` из `requirements.txt`; DOCX не требует внешнего пакета.

## Как это работает

- Офлайн-поиск — детерминированный: он ищет совпадения в клаузах текущей версии каждого документа и показывает дословную цитату, документ и версию.
- Если у LLM задана текущая OpenAI-compatible конфигурация (`LLM_PROFILE=groq` или `cps`), она лишь объясняет уже найденные фрагменты и предлагает поисковые термины. При ошибке или без конфигурации остаётся явный офлайн-режим.
- Для VPN в proxy-режиме направьте Groq через локальный прокси: `GROQ_PROXY_URL=http://127.0.0.1:10809 LLM_PROFILE=groq .venv/bin/python app.py`. Ключ передаётся отдельно через `GROQ_API_KEY` и не хранится в репозитории.
- Перед любым вызовом LLM сохраняется прежняя политика приватности: маскирование, псевдонимизация и блокировка credentials. Блок «Защита данных и настройки AI» свёрнут в UI.
- Редактируемые системные подсказки находятся в `prompts.json`, вне Python-кода.

## Два обязательных demo-сценария

1. **Спросить по ситуации.** Нажмите «Показать пример конфликта». Право на дистанционную работу сопоставляется с запретом работы с персональными данными вне защищённого офиса; побеждает стандарт ИБ, потому что в синтетическом корпусе указан `priority_rank: 1` против `2`.
2. **Выжимка документа с изменениями.** Загрузите `demo/remote-work-v2.txt`. Приложение локально узнает текущую синтетическую версию, найдёт версию 1.0 в корпусе, покажет добавленные/удалённые нормы и даст кнопку «Скачать выжимку». Тот же экран принимает TXT/MD/CSV/JSON/DOCX/PDF.

Во всех экранах метка «AI с опорой на источники» означает, что LLM объясняет только найденные фрагменты. «Офлайн-резерв» — полноценный детерминированный ответ/выжимка, когда LLM не настроена или недоступна.

## Проверки

```bash
python3 -m py_compile app.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

Для внутренней OpenAI-compatible LLM используйте существующие параметры `LLM_PROFILE=cps`, `CPS_LLM_BASE_URL`, `CPS_LLM_MODEL` и опционально `CPS_LLM_API_KEY`. Не помещайте ключи в репозиторий.
