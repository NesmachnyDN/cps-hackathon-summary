# Нормы — MVP по официальным документам

Однопроцессное Python-приложение со статическим HTML-интерфейсом. Оно отвечает на ситуационные вопросы по действующим версиям нормативных документов и делает структурированное резюме загруженного или выбранного документа.

Официальные документы хакатона хранятся только локально в `official_documents_inbox/` и исключены из Git. Скрипт `scripts/prepare_official_documents.py` конвертирует старые `.doc` в `.docx`, извлекает текст и формирует `official_documents_inbox/official_corpus.json`. Если этот корпус существует, `scripts/run_groq_proxy.sh` подключает его автоматически. Синтетический `demo/normative_corpus.json` остаётся только резервным тестовым fixture.

## Запуск на хакатоне

Первичная подготовка окружения:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Основной запуск с Groq через локальный VPN-proxy:

```bash
./scripts/run_groq_proxy.sh
```

Launcher автоматически пересобирает локальный корпус из `official_documents_inbox/original/`, подключает его, использует proxy `127.0.0.1:10809` и запускает приложение на `http://127.0.0.1:8001`. Если `GROQ_API_KEY` не задан, ключ запрашивается скрыто в терминале.

Для разработки без launcher можно явно задать `NORMATIVE_CORPUS_PATH` и `APP_PORT`.

Docker-вариант:

```bash
docker build -t cps-hackathon-summary .
docker run --rm -p 8000:8000 cps-hackathon-summary
```

Файлы TXT, MD, CSV, JSON, DOC, DOCX и PDF извлекаются локально. Старый `.doc` временно конвертируется LibreOffice и удаляется вместе с временным каталогом; PDF использует `pypdf`, DOCX разбирается локально без внешнего сервиса.

## Как это работает

- Офлайн-поиск — детерминированный: он ищет совпадения в клаузах текущей версии каждого документа и показывает дословную цитату, документ и версию.
- Если у LLM задана текущая OpenAI-compatible конфигурация (`LLM_PROFILE=groq` или `cps`), она лишь объясняет уже найденные фрагменты и предлагает поисковые термины. При ошибке или без конфигурации остаётся явный офлайн-режим.
- Для VPN в proxy-режиме направьте Groq через локальный прокси: `GROQ_PROXY_URL=http://127.0.0.1:10809 LLM_PROFILE=groq .venv/bin/python app.py`. Ключ передаётся отдельно через `GROQ_API_KEY` и не хранится в репозитории.
- Перед любым вызовом LLM сохраняется прежняя политика приватности: маскирование, псевдонимизация и блокировка credentials. Блок «Защита данных и настройки AI» свёрнут в UI.
- Редактируемые системные подсказки находятся в `prompts.json`, вне Python-кода.

## Проверка на пакете задания

1. **Спросить по ситуации.** Нажмите «Показать пример по документам»: приложение отвечает на вопрос о требуемом стаже ведущего специалиста и показывает дословный пункт из ДИ-11-992.
2. **Проверить различение похожих инструкций.** Спросите отдельно о стаже ведущего и главного специалиста: источниками должны стать соответственно ДИ-11-992 и ДИ-11-993.
3. **Выжимка документа.** На вкладке «Выжимка документа» выберите любую из пяти инструкций пакета. Если предыдущая редакция не передана, приложение явно пишет, что она не найдена, вместо выдумывания изменений.

Во всех экранах метка «AI с опорой на источники» означает, что LLM объясняет только найденные фрагменты. «Офлайн-резерв» — полноценный детерминированный ответ/выжимка, когда LLM не настроена или недоступна.

## Проверки

```bash
python3 -m py_compile app.py
python3 -m unittest discover -s tests -p 'test_*.py'
```

Для внутренней OpenAI-compatible LLM используйте существующие параметры `LLM_PROFILE=cps`, `CPS_LLM_BASE_URL`, `CPS_LLM_MODEL` и опционально `CPS_LLM_API_KEY`. Не помещайте ключи в репозиторий.
